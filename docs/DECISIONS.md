# DECISIONS

## ADR-001：线网模型独立实现，只保留与 rmg 可迁移的字段

- 日期：2026-11-28
- 状态：已采纳
- 背景：需要兼容 rmg 项目文件，但 RMGParam 把风格专用字段与站点数据混在一起，且用 `linestart / lineend` 虚拟站表达端点。
- 考虑过的方案：直接复用 RMGParam；在 RMGParam 上增量改字段；重新定义 Network 模型并提供导入器。
- 决策：在 `src/core/model.ts` 定义 `Network / Line / Station / StationPov`，导入器 `src/core/rmg-import.ts` 负责迁移旧字段与邻接表。
- 为什么选这个：物料层只需站序、换乘与线色；虚拟站点与风格字段会污染全链路。
- 为什么不选其他：直接复用会让每次增加物料都要面对整套 RMG 字段；增量改造则需要维护两套语义。
- 后果：rmg 的其余能力（库、风格组件）不能直接复用，只能参考实现。
- 何时重新审视：需要支持 rmg 全量导入或导出时。

## ADR-002：布局采用关键路径法

- 日期：2026-11-28
- 状态：已采纳
- 背景：线路可能是支线结构（主干 + 分支），需要按站数等距排列而不是地理距离。
- 考虑过的方案：手工坐标（RMP 的做法）；地理坐标投影；关键路径法（rmg 的做法）。
- 决策：`src/core/layout.ts` 内实现关键路径法（来源 rmg，GPL-3.0，文件头标注）。
- 为什么选这个：与 rmg 的物料观感一致，且直接支持支线与环线。
- 为什么不选其他：手工坐标不适合「自动从模板导入」；地理投影在示意图语境下失真。
- 后果：布局无法表达「真实走向」，仅用于路线图。
- 何时重新审视：引入地图底图时。

## ADR-003：LED 点阵用像素字体栅格化

- 日期：2026-11-28
- 状态：已采纳
- 背景：放送机与 LED 站牌需要精确点阵效果。
- 考虑过的方案：PCF 位图字体（rma 的做法，文泉驿 12pt）；Canvas 直接画文字；像素字体栅格化成 1 位点阵。
- 决策：使用 Fusion Pixel Font 12px（OFL-1.1）加载为 `FontFace`，用 Canvas 读像素覆盖率生成点阵，非满格点按覆盖率降低不透明度。
- 为什么选这个：字体许可清晰、与现有中文字形一致，且点阵坐标完全可控，SVG 导出与屏幕一致。
- 为什么不选其他：PCF 需要自研解析器且覆盖不全；直接 canvas 没有「点」的质感。
- 后果：字体增加约 1 MB，首次加载前空白；点阵严格 12 行。
- 何时重新审视：需要更大字号 LED 或其它字体时。

## ADR-004：状态管理用 zustand 而非 Redux Toolkit

- 日期：2026-11-28
- 状态：已采纳
- 背景：只有一份项目文档与少量视图状态，更新多为不可变 patch。
- 考虑过的方案：Redux Toolkit（rmg 的做法）；React context；zustand。
- 决策：`src/state/project.ts`（落盘）+ `src/state/editor.ts`（会话内）。
- 为什么选这个：样板代码少，`persist` 中间件直接满足本地保存需求。
- 为什么不选其他：Redux 的 slice/action 体系对本项目是纯开销；context 在频繁更新时会导致全树重渲染。
- 后果：持久化的数据迁移需要自行处理 `version` 字段。
- 何时重新审视：状态需要时间旅行或需要与 rmg 代码互通时。

## ADR-005：首期不做线路图编辑器

- 日期：2026-11-28
- 状态：已采纳
- 背景：需求包含「线网制作」，但线网编辑（地图底图、站点拖放、线路连接）工作量远大于物料制作。
- 考虑过的方案：先做编辑器再做物料；先做物料再补编辑器；两者并行。
- 决策：首期以物料为核心，内置合肥线网作为唯一数据源，只提供「逐站查看」；线网编辑留到后续。
- 为什么选这个：物料是验收重点，线网编辑依赖底图与交互设计，容易拖垮首版。
- 为什么不选其他：并行会让首版迟迟不能交付。
- 后果：用户暂时不能自建线网；数据模型为此预留了 `Network` 抽象与 rmg 导入。
- 何时重新审视：物料流程稳定后。
