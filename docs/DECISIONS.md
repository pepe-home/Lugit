# DECISIONS

## ADR-001：线网模型独立实现，只保留与 rmg 可迁移的字段

- 日期：2026-11-28
- 状态：已采纳
- 背景：需要兼容 rmg 项目文件，但 RMGParam 把风格专用字段与站点数据混在一起，且用 `linestart / lineend` 虚拟站表达端点。
- 考虑过的方案：直接复用 RMGParam；在 RMGParam 上增量改字段；重新定义 Network 模型并提供导入器。
- 决策：在 `src/core/model.ts` 定义 `Network / Line / Station / StationPov`，导入器 `src/core/rmg-import.ts` 负责迁移旧字段与邻接表。
- 为什么选这个：物料层只需站序、换乘与线色；虚拟站点与风格字段会污染全链路。
- 为什么不选其他：直接复用会让每次增加物料都要面对整套 RMG 字段；增量改造则需要维护两套语义。
- 后果：rmg 的其余能力（库、风格组件）不能直接复用，只能参考实现。
- 何时重新审视：需要支持 rmg 全量导入或导出时。

## ADR-002：布局采用关键路径法

- 日期：2026-11-28
- 状态：已采纳
- 背景：线路可能是支线结构（主干 + 分支），需要按站数等距排列而不是地理距离。
- 考虑过的方案：手工坐标（RMP 的做法）；地理坐标投影；关键路径法（rmg 的做法）。
- 决策：`src/core/layout.ts` 内实现关键路径法（来源 rmg，GPL-3.0，文件头标注）。
- 为什么选这个：与 rmg 的物料观感一致，且直接支持支线与环线。
- 为什么不选其他：手工坐标不适合「自动从模板导入」；地理投影在示意图语境下失真。
- 后果：布局无法表达「真实走向」，只用于线网工作区的线路示意。
- 何时重新审视：引入地图底图时。

## ADR-003：LED 点阵用像素字体栅格化

- 日期：2026-11-28
- 状态：已采纳
- 背景：放送机与 LED 站牌需要精确点阵效果。
- 考虑过的方案：PCF 位图字体（rma 的做法，文泉驿 12pt）；Canvas 直接画文字；像素字体栅格化成 1 位点阵。
- 决策：使用 Fusion Pixel Font 12px（OFL-1.1）加载为 `FontFace`，用 Canvas 读像素覆盖率生成点阵，非满格点按覆盖率降低不透明度。
- 为什么选这个：字体许可清晰、与现有中文字形一致，且点阵坐标完全可控，SVG 导出与屏幕一致。
- 为什么不选其他：PCF 需要自研解析器且覆盖不全；直接 canvas 没有「点」的质感。
- 后果：字体增加约 1 MB，首次加载前空白；点阵严格 12 行。
- 何时重新审视：需要更大字号 LED 或其它字体时。

## ADR-004：状态管理用 zustand 而非 Redux Toolkit

- 日期：2026-11-28
- 状态：已采纳
- 背景：只有一份项目文档与少量视图状态，更新多为不可变 patch。
- 考虑过的方案：Redux Toolkit（rmg 的做法）；React context；zustand。
- 决策：`src/state/project.ts`（落盘）+ `src/state/editor.ts`（会话内）。
- 为什么选这个：样板代码少，`persist` 中间件直接满足本地保存需求。
- 为什么不选其他：Redux 的 slice/action 体系对本项目是纯开销；context 在频繁更新时会导致全树重渲染。
- 后果：持久化的数据迁移需要自行处理 `version` 字段。
- 何时重新审视：状态需要时间旅行或需要与 rmg 代码互通时。

## ADR-005：线网编辑从站点级升级为地图拖放编辑

- 日期：2026-11-28
- 状态：已采纳（取代本文件中「先做站点级、不做地图底图」的初版）
- 背景：站点级编辑只能改顺序，无法表达真实走向，也无法建立线间换乘；需求明确要求地图底图与拖放绘制。
- 考虑过的方案：保留纯文本站序编辑；自绘 Canvas 地图；Leaflet + 在线瓦片 + 站点坐标。
- 决策：引入 Leaflet 与在线瓦片（高德 / CARTO / OSM / 无底图），为全部站点补 WGS-84 坐标；线路按站点顺序连线；拖动站点改坐标，点击地图追加站点；文本站序编辑保留为精细调整。
- 为什么选这个：Leaflet 成熟、可动态拆包；瓦片无需自建；地图与站序编辑共用 `Network`，物料不受影响。
- 为什么不选其他：自绘地图要自己实现投影、缩放与瓦片交互；纯文本编辑满足不了真实地理要求。
- 后果：需要联网加载瓦片；线路仍是站间直线，不支持曲线、共线与真实轨道线形；编辑没有撤销栈。
- 何时重新审视：需要自由绘制线形、离线底图或撤销 / 重做时。

## ADR-006：右侧栏用「线网 / 车站」两个工作区组织

- 日期：2026-11-28
- 状态：已采纳
- 背景：三种物料都属于某一座车站，而线路与站点结构不属于任何一站；把它们平铺在一个面板里会混淆「改数据」与「做物料」。
- 考虑过的方案：单面板按物料切换；顶部全局导航分页；右侧栏标签页分工作区。
- 决策：右侧栏顶部标签切换工作区；「线网」工作区编辑线路与站点（地图 / 示意两种视图），「车站」工作区选定车站后制作三件物料。
- 为什么选这个：工作区与数据层级一致（线网 → 车站 → 物料），切换成本最低，且线网编辑不会误改物料参数。
- 为什么不选其他：顶部全局导航会占掉预览区高度；单面板无法同时表达「线网」与「车站」两层。
- 后果：物料导出始终针对当前车站；地图与示意只存在于线网工作区。
- 何时重新审视：需要同时展示多站物料或整线批量导出时。

## ADR-007：站点坐标存 WGS-84，高德底图渲染时转 GCJ-02

- 日期：2026-11-28
- 状态：已采纳
- 背景：高德瓦片使用 GCJ-02，而公开坐标数据（Wikidata / OSM）是 WGS-84；混用会让站点偏移约 500 米。
- 考虑过的方案：只支持 WGS-84 底图；只支持高德并把坐标存 GCJ-02；存 WGS-84，按底图换算。
- 决策：`Station.geo` 一律存 WGS-84；渲染前通过 `src/lib/coord.ts` 转成当前底图的基准，拖动结果反向转回并落盘。
- 为什么选这个：数据层保持单一、可迁移的基准，同时保留高德底图在国内的加载速度与中文注记。
- 为什么不选其他：只支持 WGS-84 会牺牲国内可用性；存 GCJ-02 会污染数据层，换底图或导入数据都要重新标定。
- 后果：地图渲染多一层坐标换算；新增底图必须声明 `gcj` 标志。
- 何时重新审视：引入国内其他 GCJ-02 底图或离线瓦片时。

## ADR-008：换乘由共站推导，拖到一起即建立

- 日期：2026-11-28
- 状态：已采纳
- 背景：需求要编辑「线与线之间的关系」，核心是换乘；单独维护换乘表容易与站序脱节。
- 考虑过的方案：独立换乘表；在站点上手工勾选可换乘线路；同一站点记录被多条线共用。
- 决策：换乘 = 「同一站点 id 出现在两条及以上线路」，由 `recomputeTransfers` 推导；把两条线的站合并（拖拽或面板）即建立换乘，拆分即生成独立站。
- 为什么选这个：换乘与站序天然一致，删线、调序、改名都不需要额外同步；地图拖放可以直接表达意图。
- 为什么不选其他：独立换乘表要处理两套 id 与引用完整性；手工勾选无法表达「两座同名但不同位置的车站」。
- 后果：合并会删除被并入的站点记录；拆分产生同名新站，需要用户自行改名区分；不支持出站换乘的细分类别。
- 何时重新审视：需要出站换乘、同名不同站或换乘通道信息时。
